# Capstone: Low-Code vs Full-Code Options

There are two ways to complete the Capstone project:

1. **Full-code** — Write the solution from scratch and submit a final Jupyter notebook with all insights and observations.
2. **Low-code** — Use the provided solution notebook template to build the solution, then submit a business report with insights and recommendations.

These options let you choose the approach that fits your goals (hands-on coding vs. solution review and business communication).

---

## Comparison

| | Full-code | Low-code |
|--|-----------|----------|
| **Who should choose** | Learners aiming for hands-on coding roles, focused on building solutions from scratch | Learners aiming for managerial roles, focused on solution review, interpretation, recommendations, and business communication |
| **What is the same** | Both perform exploratory data analysis and identify insights and recommendations for the problem | |
| **What is different** | 10–20% of grading on **quality of the final code** | 10–20% of grading on **quality of the final business report** |
| **Final submission** | Solution notebook (from full-code template) as **.html** | Business report as **.pdf** (problem definition, insights, recommendations) |
| **Submission format** | `.html` | `.pdf` |

**Important:** If you submit both a report and a notebook, **only the report will be evaluated**. Ensure all rubric sections are covered in your submission.

---

## How to Complete the Assessment

### Full-code version

1. Download the full-code learner notebook.
2. Follow the instructions in the notebook to complete the project.
3. Document insights and recommendations in comments.
4. Submit **only** the solution notebook derived from the learner notebook — **format: .html**.

### Low-code version

1. Download the low-code learner notebook.
2. Follow the instructions in the notebook to complete the project.
3. Prepare a business report with insights and recommendations.
4. Submit **only** the business report — **format: .pdf**.

---

## Submission Rules

1. **Plagiarism** — Copied or plagiarized work will not be graded and will receive zero marks.
2. **Deadline** — Submissions after the deadline will not be accepted.
3. **Submissions will not be evaluated if:**
   - They are submitted after the deadline, or
   - More than one file is submitted.

## Best Practices

### Full-code submissions

- **Documentation** — Use inline comments for code and markdown cells for observations and insights.
- **Execution** — Run the notebook start to finish in order before submitting.
- **Clean output** — Remove all warnings and errors before submission.
- **Format** — Submit as **.html**, not .ipynb.
- See the FAQ page for common project-related queries.

### Low-code submissions

- **Audience** — Write for a Data Science lead.
- **Content** — Include:
  - Business overview of the problem and solution approach
  - Key findings and insights that can drive decisions
  - Business recommendations
- **Clarity** — Explain takeaways in simple, easy-to-understand language.
- **Impact** — Including potential benefits of implementing the solution will strengthen your report.
- **Style** — Avoid copying from the notebook; show code only when it is the focal point.
- **Format** — Submit as **.pdf**, not .doc.
- See the FAQ page for common project-related queries.
